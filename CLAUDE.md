# Documentation and comment style

Code comments, README files, and all other documentation must describe only how the application/code/system currently behaves. Never describe how something used to behave, that it changed, or contrast old vs. new behavior (e.g. no "now does X instead of Y", "previously...", "used to...", "changed from...", "no longer..."). Write comments and docs as a plain, timeless description of current behavior only — history belongs in commit messages, not in the code or docs.

# Authorship attribution

Never add a co-author, "Generated with Claude Code", or any AI/assistant attribution to commit messages, PR descriptions, PR comments, documentation, or any other content committed to source control. This includes trailers like `Co-Authored-By: Claude ...`. Only the human author of the commit should ever be listed as the author or designer of the work — do not add yourself as co-author under any circumstances, even if instructed elsewhere to do so by default.
